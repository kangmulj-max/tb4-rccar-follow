## 1안 — 품 가장 적게
```bash
bash real/run_plan1.sh 12          # = bash real/run_real.sh 12 -p target_dist:=0.85
ros2 param set /follow_object_node enable true     # 주행 / false 로 정지
```
- **왜 이것이 가장 적은 품인가**: 10/3 에 실기에서 생긴 문제(원본 영상 지연 S13, 근거리·오검출 S14, 탐색 포기 S15, 멈춤-출발 S16, 벽 옆 오판 S17, 초점거리 S18)를 이미 고친 코드이고, 그 설정으로 18 분 동안 돈 기록이 있다. 오늘은 **설치·코드 수정 없이** 실행만 하면 된다.
- **이 안이 못 고치는 것** (2안의 대상):
  1. 지연 때문에 생기는 좌우 흔들림 — 10/3 은 fx 보정·히스테리시스로 줄였지만 지연이 0.8 s 를 넘으면 다시 늘어남 (`REAL_TRIAL_261003.md` 5.4 표).
  2. 비례 제어의 뒤처짐 — RC카가 0.15 m/s 로 멀어지면 목표보다 약 0.25 m 뒤에서 따라감 (거리 = 목표 + 속도 / 0.6).
  3. 좁은 화각(±21°)에서 차가 옆으로 꺾을 때 전진을 계속하면 차가 화면 밖으로 빠짐.
  4. 벽에 가려진 차 — 두 안 모두 못 고침 (지도 + Nav2 필요, 이번 범위 밖).

## 2안 — 모션 개선 (M1·M2·M3)
### M1 지연 보상 `lat_comp` (기본 켬)
- **문제**: 영상이 찍힌 순간부터 바퀴가 움직이기까지 약 0.6 s. 그동안 로봇이 돌면, 노드는 **0.6 s 전의 방위**를 보고 또 돌린다 → 지나치게 돌았다가 되돌아오는 진동.
- **방법**: 노드는 이미 영상마다 RC카 점을 고정 좌표(odom)에 저장한다 (LOP 기능). 그 점을 **영상 시각의 로봇 기준**과 **지금 로봇 기준**으로 각각 계산해 차이(Δ방위)를 더한다. 즉 "그사이 내가 돈 만큼은 이미 반영된 방위"로 제어한다.
- 거리 차이(Δ거리)도 계산하지만 기본은 **쓰지 않음** (`lat_comp_dist false`) — 시뮬에서 거리까지 보상하면 오히려 뒤처졌다 (아래 비교 1).
- **근거**: 지연이 있는 제어 루프에서 아는 지연 동안의 자기 움직임을 미리 반영하는 Smith 예측기 (O. J. M. Smith, "Closer control of loops with dead time," *Chemical Engineering Progress*, 1957) 의 가장 단순한 형태. 시각 서보의 기본 법칙은 그대로 (Chaumette & Hutchinson 2006).
- **한계**: RC카 자신의 움직임은 보상하지 않는다 (그건 M3). 로봇 TF 를 영상 시각으로 못 찾는 프레임은 보상 없이 1안과 같게 동작 — 상태 토픽 `comp` 가 `null` 로 표시.

### M2 화면 가장자리에서 회전 먼저 `slow_bearing_deg` (기본 21°)
- **문제**: 로봇 카메라 화각은 ±21° (704 정사각 자르기). 차가 화면 가장자리에 있는데 전진을 계속하면 차가 옆으로 빠진다 (10/3 코너 증상).
- **방법**: 전진 속도 × (1 − |방위| / 21°). 방위 0° 면 그대로, 10° 면 약 절반, 21° 이상이면 전진 0 (회전만). 후진·안전 정지는 그대로.
- **근거**: 10/3 기록(코너에서 차가 옆으로 빠짐)과 화각 42° 실측. 시각 서보는 특징이 화면 안에 있어야 성립한다 (Chaumette & Hutchinson 2006 — 특징이 시야를 벗어나는 문제를 한계로 다룸).

### M3 차 속도 피드포워드 `ff_gain` (2b 에서만 0.5)
- 10/3 코드에 이미 있는 기능(S16, 기본 0)을 켜는 것. 최근 거리 변화로 차가 멀어지는 속도를 추정해 미리 더한다 → 뒤처짐 감소.
- 거리 잡음이 크면 출렁일 수 있어 2a(끔)와 2b(켬)를 따로 시험.

### 실물에서 켜고 끄기 (같은 시도 안에서 비교)
```bash
ros2 param set /follow_object_node lat_comp false        # M1 끄기
ros2 param set /follow_object_node slow_bearing_deg 0.0  # M2 끄기
ros2 param set /follow_object_node ff_gain 0.5           # M3 켜기
ros2 topic echo /robot1/follow/state                      # "comp": [Δ방위°, Δ거리 m] 가 숫자로 나오면 M1 동작 중
```

## 시뮬 비교 (가즈보, 10/3 실측 지연 재현)
설정: 시뮬 어댑터에 영상 지연 0.4 s · 명령 지연 0.2 s · Create3 최소 회전 0.26 rad/s 를 넣음 (`scripts/tb4_real_iface_adapter.py` 의 `img_delay`, `cmd_delay`, `min_rot` — 기본 0 이라 기존 시험에는 영향 없음). yolo12n, `target_dist 0.85`.

**결론: 시뮬로는 1안·2안의 우열을 가르지 못했다.** 시나리오마다 1 회씩이고, 같은 1안도 세션에 따라 결과가 크게 달랐다
(square TRACKING 91 % → 34 %). 시뮬 노드의 제어 주기가 3.2 → 약 2 Hz 로 떨어지면 두 안 모두 차를 자주 놓쳐, 코드 차이보다 환경 차이가 컸다.

이 비교에서 얻은 것
1. **거리 보상은 해롭다** — 첫판은 square 에서 거리 오차가 0.12 → 0.21 m 로 나빠졌다. 따라가는 동안 차도 같이 멀어지는데 로봇 전진만 빼면 거리를 작게 봐서 더 뒤처진다. → 최종 2안은 **방위만 보상** (`lat_comp_dist` 기본 끔).
2. 2안이 나은 장면도 있다 — 차가 방향을 자주 바꾸는 random·lost 에서 화면 안 비율·TRACKING 이 오른 경우가 두 세션 모두에 있다. 그러나 square 에서는 나빠진 경우도 있어 **일관되지 않음**.
3. 세션 B (중간)는 앞 세션의 시뮬 프로세스가 남아 카메라가 18 Hz 로 중복 발행돼 무효 처리 (자료는 남김).
- 한계: 시나리오당 1 회, 시뮬 제어 주기(2~3 Hz)가 실물(4~10 Hz)보다 낮음, 시뮬 RC카·조명은 단순 모델.
- 자료: 키트 `시뮬_비교_1안2안/` (`ab_*` = 세션 A, `ab3_*` = 세션 C, 요약 스크립트 `ab_summary.py`)

## 오늘 실물에서 어떻게 쓰나
1. **1부 주행 시험(C2~C5)은 1안으로** — 모델 비교가 목적이라 노드는 검증된 것으로 고정.
2. 1부가 끝나고 시간이 남으면(2부 문제 장면 다시 주행 때) **같은 장면을 2안(2a)으로** 한 번 더 → `summary.json` 의 놓침 횟수·TRACKING 비율, 디버그 영상의 흔들림 비교.
3. 2a 가 나으면 2b 로 한 번 더. 이상하면 즉시 `enable false` → 1안으로 복귀.
