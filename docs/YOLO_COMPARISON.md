# YOLO8n · YOLO11n · YOLO12n — 공식 자료와 실측 대조 (RC카 추종 관점)

이 문서의 숫자는 두 종류다. **[공식]** = 논문·Ultralytics 문서 (COCO 80 클래스, 사전학습 모델) / **[실측]** = 이 프로젝트 가중치(`yolo8n_amr_best.pt`, `yolo11n_amr_best.pt`, `yolo12n_amr_best.pt`, 2 클래스)로 잰 값.
다른 모델을 추가 비교할 때는 9절 절차를 그대로 따르면 같은 표에 누적된다. **yolo8n 은 2026-10-04 에 추가** — 10절.

## 0. 3 모델 요약 (2026-10-04, 10절)
- **yolov8n 은 이 프로젝트에 맞지 않는다.** 같은 데이터·같은 학습 조건인데 움직이는 RC카 추종 유지율 10~14 % (11n 64~72 %, 12n 77~78 %, 같은 회차).
  원인: 시뮬 RC카를 **dummy(검은 상자)로 오분류** 하는 비율이 47~59 % 로 가장 높다. 실물 데이터셋 지표(mAP)는 셋 중 가장 높아(0.977 / 0.917) 지표만 보면 반대로 고르게 된다.
- 속도는 8n 이 GPU 에서 가장 빠르고(6.8 ms) CPU 는 11n 과 비슷(23.6 ms) — 느려서가 아니라 **오분류** 때문에 실패.
- 11n vs 12n 의 순위(추종은 12n 우세)는 이번 회차에서도 같았다 → 세 회차 연속 같은 방향.

## 1. 한 줄 요약 (11n vs 12n, 2026-10-03 기준)
- 실물 데이터셋 지표로는 **우열을 가릴 수 없다** (둘 다 mAP50 0.995, valid/test 대부분이 train 과 같은 원본).
- **속도**는 yolo11n 이 확실히 빠르다 (GPU 1.4~1.6 배, CPU 1.2~1.3 배).
- **감지**는 조명에 따라 순위가 뒤집힌다: 밝으면 12n, 어두우면 11n. 12n 이 조명 변화에 더 민감 (59 → 28 %).
- **움직이는 RC카 추종**은 yolo12n 이 우세 (평균 추종 유지율 81 % vs 74 %, v3_safe 에서 81 % vs 66 %). 단 원거리 정지 타깃의 첫 포착은 12n 이 약함.
- 실기 선택은 실습장 조명에서 bag 을 녹화해 두 모델을 같은 장면으로 재생 비교한 뒤 결정할 것.

## 3. 성능 수치 대조

### 3-1. 공식 (COCO val2017, 640)
| 모델 | mAP50-95 | CPU ONNX | T4 TensorRT | params | FLOPs |
|---|---|---|---|---|---|
| YOLO11n [Ultralytics] | 39.5 | 56.1 ms | 1.5 ms | 2.6 M | 6.5 G |
| YOLO12n [Ultralytics 문서] | 40.6 | 미기재 | 1.64 ms | 2.6 M | **7.5 G** |
| YOLOv12-N [arXiv v1] | 40.6 | — | 1.64 ms | 2.6 M | 6.5 G |
| YOLOv12-N [NeurIPS 판] | 40.5 | — | 1.62 ms | — | — |
| YOLOv12-N turbo [원저자 GitHub] | 40.4 | — | 1.60 ms | 2.5 M | 6.0 G |

→ 같은 "YOLO12n" 이라도 판본마다 수치가 다르다. FLOPs 는 Ultralytics 통합본(7.5 G)이 논문(6.5 G)보다 크다.
→ 논문 주장: YOLOv12-N 이 YOLO11-N 보다 mAP +1.2 (NeurIPS 판 +1.1), 속도는 비슷.

| GFLOPs (2 클래스, 비융합) | 6.5 | 7.46 | 12n 이 더 큼 = Ultralytics 문서 7.5 G 와 일치 (논문 6.5 G 와 불일치) |
| 파일 | 5.48 MB | 5.53 MB | |
| 어텐션 구현 | — | **FlashAttention 미사용** (8.4.171 `AAttn` 은 일반 행렬곱+softmax) | 문서의 FlashAttention 가속은 이 환경에 해당 없음 |
| 실물 valid mAP50 / 50-95 | 0.995 / **0.971** | 0.995 / 0.950 | 포화 — 아래 4절 주의 |

| 지연 CPU (PyTorch) | **22~26 ms** | 28~35 ms | Ultralytics "12 는 CPU 처리량 저하" 경고와 방향 일치 |

(지연은 시뮬을 끈 상태에서 두 번 잰 범위. 시뮬이 돌 때는 GPU 9.2/13.3, CPU 63/92 ms 로 늘어남 — 실기 노트북에서도 다른 프로그램 부하에 따라 달라짐)

### 3-3. 시뮬 감지율 (같은 32 자세: 거리 0.8/1.2/1.8/2.5 m × 방향 8, conf ≥ 0.4)
| 조명 | yolo11n | yolo12n |
|---|---|---|
| 밝음 (`follow_arena_bright`) | 46.9 % (평균 conf 0.41) | **59.4 %** (0.49) |
| 어두움 (`follow_arena`, 매트릭스 조건) | **62.5 %** (0.54), dummy 오분류 25 % | 28.1 % (0.26), dummy 오분류 37.5 % |

- 12n 은 조명이 어두워지면 감지율이 절반 이하로 떨어지고 RC카를 dummy 로 오분류하는 비율이 커진다.
- 11n 은 두 조명에서 47~63 % 로 상대적으로 안정적이지만, 밝은 조명에서 정면·정후면(0°, 180°)을 전혀 못 잡는 등 자세별 편차가 크다.
- 두 모델 모두 **옆모습(90°, 270°)** 이 약하다 — 학습 데이터에 옆모습이 적고 dummy(검은 상자)와 실루엣이 비슷함. 녹화 영상에서도 옆모습이 `dummy 0.44` 로 찍힌 장면 확인.
- 표본: 자세당 1 프레임, 32 자세. 렌더링은 결정적이라 잡음은 없지만 자세 수가 적어 ±10 %p 차이는 의미 있게 보지 말 것.
- 시뮬 RC카는 사진이 아니라 단순 도형 모델 → 실물과 외형이 다르다. **절대 수치가 아니라 '조건이 바뀌면 순위가 바뀐다' 는 경향**이 결론.

## 4. 추종 매트릭스 (움직이는 RC카, v3 / v3_safe)
같은 시나리오·같은 조건(어두운 조명 월드, 녹화 포함)에서 4 조합을 1 회씩 실행. 지표 정의는 `scripts/follow_metrics.py`.
**추종 유지율** = RC카가 움직이는 동안 TRACKING 이면서 카메라↔RC카 거리가 1.0 ± 0.6 m 인 시간 비율.

| 시나리오 | v3 + 11n | v3 + 12n | v3_safe + 11n | v3_safe + 12n |
|---|---|---|---|---|
| square | 81.4 % | 98.9 % | 80.8 % | 97.6 % |
| random | 56.7 % | 68.5 % | 49.8 % | 92.7 % |
| stopgo | 57.7 % | 48.2 % | 63.4 % | 61.7 % |
| lost | 79.1 % | 80.7 % | 90.3 % | 77.4 % |
| camdrop | 68.2 % | 90.4 % | 54.9 % | 97.7 % |
| **평균** | **73.9 %** (놓침 8회) | **81.1 %** (5회) | **65.7 %** (8회) | **80.6 %** (4회) |

| 추종 시나리오 합계 | TRACKING 비율 | TRACKING→REID 횟수 | 거리오차 평균 |
|---|---|---|---|
| v3 + 11n | 70 % | 100 | 0.226 m |
| v3 + 12n | 81 % | 86 | 0.228 m |
| v3_safe + 11n | 70 % | 117 | 0.227 m |
| v3_safe + 12n | 86 % | 79 | 0.181 m |

해석
- 추종에서는 **yolo12n 이 일관되게 우세** (평균 +7~15 %p, REID 전환도 적음). 매트릭스 월드(어두운 조명)에서 정지 자세 감지율은 11n 이 높았는데(3-3) 추종은 12n 이 낫다 → **정지 사진 감지율과 실제 추종 성능은 다르다**. 따라갈 때는 대부분 뒷모습·근거리이고, 추적기가 프레임 사이를 이어주기 때문.
- 다만 정지한 RC카를 2 m 밖에서 처음 잡는 경우(pole 시나리오)는 12n 이 실패(TRACKING 0 %), 11n 은 성공 → 12n 은 **원거리 정지 타깃의 첫 포착이 약함**.
- **실행마다 ±10 %p 흔들린다**: 같은 v3 코드의 앞 회차 평균은 11n 61.0 % / 12n 74.4 %, 이번 회차 73.9 % / 81.1 %. 시나리오 1 개에서의 10 %p 이내 차이는 우연일 수 있다. 모델 순위(12n > 11n)는 두 회차 모두 같았다.

## 6. 결론 (현재 근거 기준)
1. 실물 지표로는 차이 없음 → 지표로 고르지 말 것.
2. **이 프로젝트의 목적(움직이는 RC카 추종)에는 현재 근거로 yolo12n 이 낫다** — 두 회차 매트릭스 모두 12n 우세.
3. 11n 은 속도(1.4 배)와 조명 변화에 대한 안정성, 원거리 정지 타깃 첫 포착이 낫다 → 노트북 CPU 실행이나 조명이 자주 바뀌는 곳이면 재검토.
4. 실습장 형광등은 밝은 편 → 12n 이 유리할 가능성이 있지만, 창가 역광·저녁 조명에서 급락 위험.
5. **결정 방법**: 실기에서 `record_real.sh` 로 RC카 주행 bag 을 조명별로 녹화 → 같은 bag 을 두 모델로 재생 → 추종 유지율·놓침 횟수 비교 (실험일지에 기록).
6. 근본 개선은 데이터: 다른 장소·조명·옆모습 추가, valid/test 를 train 과 다른 원본으로.

## 7. 주의할 오해
- "12 가 11 보다 최신이니 더 좋다" — 공식 COCO 기준 +1.1 mAP 이지만, 소규모 커스텀 데이터·다른 하드웨어에서는 보장되지 않는다 (이 프로젝트에서 조명 따라 역전).
- "FLOPs 가 같으니 속도도 같다" — 어텐션은 FLOPs 대비 메모리 접근이 많아 FlashAttention 없이 느리다 (실측 1.6 배).
- "mAP 0.995 니 거의 완벽" — 같은 원본의 중복 이미지로 평가된 값.

## 9. 다른 모델 추가 비교 절차
1. 같은 데이터(`amr_dataset.zip`)·같은 학습 조건(3-2 표의 학습 조건)으로 학습한 `.pt` 를 `weights/` 에 넣는다 (이름 예: `yolo26n_amr_best.pt`).
2. 오프라인 지표·지연: `python scripts/model_bench.py weights/<모델>.pt` (시뮬 끈 상태)
3. 조명별 감지: 시뮬을 `world_file:=follow_arena_bright` / 기본으로 각각 띄우고 `--sweep --light bright|dim`
4. 추종 매트릭스: `run_follow.sh` 는 `yolo${V}n_amr_best.pt` 를 찾으므로 V 에 `26` 처럼 넣으면 됨 → `NODE=v3safe bash experiment.sh square 26` 등
5. `MODELS="8 11 12" python3 scripts/summarize2.py` → 모델 열이 자동으로 늘어남, `logs/models/bench.md` 에도 행 추가
   (매트릭스는 `VERS="8 11 12" bash run_batch2.sh`, 끊기면 `RESUME=1` 로 이어서)
6. 실기: 같은 bag 재생으로 비교, 실험일지에 모델 이름 기록

### 10-2. 학습 [실측]
- `yolov8n.pt`(COCO 사전학습) → 같은 데이터(`amr_dataset`, train 81 장)·같은 조건(100 epoch, patience 20, batch 32, 640, mosaic 1.0, scale 0.5, ultralytics 8.4.171) 으로 학습. 100 epoch 완주.
- 차이: 11n·12n 은 팀이 Colab 에서, 8n 은 이 PC(RTX 3060) 에서 학습. 학습 시드·하드웨어에 따른 편차는 1 회 학습이라 확인하지 못함.

배치 중 다른 세션의 시뮬 정리 스크립트·WSL GPU 오류로 두 번 끊겨, 34 회 완료 시점에서 멈춤. 아래는 **끝까지 돈 실행만**.

### 10-6. 결론
1. 8n 은 후보에서 제외. 학습을 다시 해도 데이터(옆모습·조명·dummy 와 비슷한 실루엣)가 그대로면 같은 오분류가 날 가능성이 큼.
2. 11n vs 12n: 추종은 12n, 속도·조명 안정성은 11n — 기존 결론 유지. 실물 bag 으로 최종 결정.
3. **mAP 로 모델을 고르면 안 된다**는 근거가 하나 더 생김 (8n 이 mAP 1 위, 추종 꼴찌).
